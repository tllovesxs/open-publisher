# v0.1 acceptance baseline

Open Publisher v0.1 is a local-first demonstration release. It proves the complete product
boundary with deterministic mock providers; it does not claim that unattended real-platform
publishing is production ready.

## One-minute demo

On a clean development checkout, a contributor can:

1. start the desktop web workspace and the local Python runtime;
2. open a Markdown article and create a new immutable revision;
3. run the default multi-agent workflow with the mock provider;
4. inspect research, outline, draft, review, risk, visual-plan, and platform-variant artifacts;
5. approve a publish plan;
6. enqueue the same plan twice and observe one durable publish job;
7. simulate a successful draft handoff and inspect its receipt;
8. export a ContentPackage v1 directory that Wandao can consume as ordinary Markdown and assets.

## Required safety properties

- The WebView never receives provider or platform secrets.
- A workflow run records an immutable snapshot and input revision.
- Agent output cannot publish by itself.
- Every remote-write-shaped operation has an idempotency key.
- An ambiguous timeout enters `UNKNOWN`; it is reconciled before retry.
- Browser-session tasks contain article data and a nonce, never browser cookies.
- Final publication is disabled in the default tests and demo adapters.
- Skipping an optional workflow node is explicit and visible in the run event stream.
- Required policy nodes cannot be removed from a workflow.

## Deferred real-world tests

The following require private credentials or live platform accounts and are intentionally outside
the default test suite:

- WeChat material upload, draft creation, and publication;
- CSDN and Toutiao DOM compatibility against current editors;
- model-provider rate limits and long-running image generation;
- signed Windows and macOS release bundles;
- sleep, restart, network-loss, and duplicate-delivery recovery;
- scheduled execution while the desktop is closed.

Each live adapter must ship its own capability probe and opt-in test marker before it can be
described as supported.

An explicitly overridden Tauri UI-shell bundle is useful only for local layout inspection. It is
not an acceptance artifact because the Python Sidecar is not packaged with it.
