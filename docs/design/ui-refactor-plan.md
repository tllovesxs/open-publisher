_以桌面端内容创作为核心，参考 Airbnb 的图片优先体验，但建立稿流自己的编辑器与素材工作台。_

| 项目 | 内容 |
| --- | --- |
| 方案版本 | `0.1` |
| 方案状态 | Approved for implementation / 待按阶段实施 |
| 制定日期 | 2026-08-04 |

## 🎯 重构结论

### 本次要解决的问题

当前界面不是单纯“颜色不好看”，而是信息架构、空间分配和状态反馈同时存在问题：

1. 全局四步进度条占据约一整行高度，但用户并不按线性步骤操作，也无法通过它导航。
2. 左侧主导航 `224px` 偏宽，品牌区和状态区占用过多横向空间。
3. 文章列表固定占据一列，无法折叠或按窗口调整宽度。
4. 编辑器、预览、AI 侧栏和底部工作流面板同时出现，形成四个注意力中心。
5. AI 创作动态与 AI 修改属于同一个文章协作过程，却分散在右侧和底部。
6. 工作流失败卡、悬浮进度卡和底部动态会重复展示相同状态。
7. 素材卡片把三组表单永久展开，图片反而不是视觉主体。
8. 页面内边框过多、层级相近，白色区域之间主要依赖分割线，没有清晰主次。
9. 样式集中在约 10 万字符的单个 `styles.css`，新旧规则互相覆盖，迭代风险越来越高。
10. `App.tsx` 同时持有大量业务状态和页面拼装，视觉重构容易误伤已经接通的功能。

### 最终方向

界面采用“白色内容画布 + 轻微暖灰背景 + 单一珊瑚红强调”的内容工作台风格：

- 主内容和编辑器保持纯白；
- 左侧导航使用很浅的透明灰蓝渐变，不做纯黑或高饱和色块；
- 只在主操作、选中素材、运行状态和键盘焦点使用强调色；
- 依靠尺寸、留白和表面色差建立层级，避免到处画框和堆阴影；
- 图片卡片借鉴 Airbnb 的 photo-first 结构；
- 编辑器和 AI 协作区保持 Codex 一类生产力工具的克制密度；
- 不使用 Airbnb Logo、品牌字体、旅游图标、文案或完整品牌色系统。

### 必须执行的删减

- 删除所有页面顶部的 `LifecycleRail` 四步进度条。
- 删除文章页底部独立的“AI 创作动态”工作区。
- 删除重复的右下角运行进度悬浮卡。
- 删除重复的右下角失败悬浮卡。
- 删除不承担实际操作的装饰性机器人悬浮图；只允许在空状态中作为插图出现。
- 不在每张素材卡下面永久显示多组 `textarea`。
- 不使用整块高饱和颜色表示当前导航。
- 不为每个白色面板都增加边框、圆角和阴影。

### 保留的产品结构

五个一级页面保持不变：

1. 创作；
2. 文章；
3. 模板；
4. 素材库；
5. 设置。

发布仍是文章页中的操作，不新增一级页面。Agent 页面不恢复。

## 🎨 视觉系统

### 设计借鉴边界

Airbnb 参考用于：

- 图片承担卡片主要视觉重量；
- 图片区域约 `14px` 圆角；
- 图片上的选择、预览和更多操作使用悬浮圆形按钮；
- 卡片主体默认无重边框；
- 白色页面只使用一档轻阴影；
- 4/8px 间距体系；
- 温和的中等字重和较少的品牌色。

稿流不采用：

- Airbnb Cereal 等未授权字体；
- Airbnb Logo、房源心形收藏语义和旅行分类图标；
- 完整照搬 `#ff385c` 品牌身份；
- 64px 旅游搜索条和房源价格卡片结构；
- 面向消费者商城的夸张留白。

### 字体

```css
--font-ui: Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--font-reading: "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-code: "JetBrains Mono", "Cascadia Code", Consolas, monospace;
```

- 不打包 Airbnb Cereal。
- UI 标题使用 `Inter`/中文系统字重 `600`，不使用大面积 `700/800`。
- Markdown 源码使用等宽字体。
- 文章预览使用中文阅读字体，正文 `16–17px / 1.75`。
- 普通 UI 正文 `14px / 1.5`，辅助文字不小于 `12px`。

| Token | 值 | 用途 |
| --- | ---: | --- |
| `--radius-xs` | 6px | 小徽标、细小控件 |
| `--radius-sm` | 8px | 按钮、输入框 |
| `--radius-md` | 12px | 浮层、小面板 |

| `--radius-lg` | 18px | 模态框、详情抽屉 |
| `--radius-pill` | 999px | 筛选标签、状态和圆形图标按钮 |

不再给所有卡片统一 `24px` 大圆角。编辑器等严肃工作区主要使用直线边界。

### 阴影

全局只保留一档浮层阴影：

```css
--shadow-float:
  0 0 0 1px rgb(0 0 0 / 2%),
  0 2px 6px rgb(0 0 0 / 4%),
  0 8px 20px rgb(0 0 0 / 8%);
```

允许使用的位置：

- 模态框和详情抽屉；
- 素材卡片悬浮操作；
- 当前拖拽预览；
- 文章列表折叠后的浮出面板。

普通页面、编辑器、导航和静态卡片不加阴影。

### 间距

以 4px 为最小单位：

```text
2 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
```

- 控件内部：8、12、16；
- 面板内边距：16、20、24；
- 页面区块：24、32；
- 图片网格：16；
- 不出现 13、17、23 等无体系间距。

### 动效

- 悬停和按下：`140–180ms`；
- 抽屉、面板和内容替换：`200–240ms`；
- 模态框：进入 `220ms`，退出 `160ms`；
- 只动画 `transform` 和 `opacity`；
- 面板折叠使用 Grid/Flex 状态切换，动画结束后再释放布局；
- 用户运行停止后立即响应，不等待退出动画；
- `prefers-reduced-motion` 下取消位移和缩放，只保留必要淡入淡出。

本次唯一具有辨识度的动效是：素材被选中时，图片外缘出现珊瑚色选择环，左上角选择按钮从空心平滑变为勾选；不在其他页面复制这一动效。

## 📐 应用布局

### 桌面尺寸基线

| 区域 | 默认宽度/高度 | 可调整范围 |
| --- | ---: | ---: |
| 主导航 | 184px | 紧凑态 64px |
| 页面顶栏 | 56px | 固定 |
| 文章列表 | 248px | 208–320px，可折叠为 0 |
| AI 侧栏 | 344px | 300–420px，可折叠为 52px |
| 编辑器/预览工具栏 | 44px | 固定 |
| 编辑器状态栏 | 28px | 固定 |
| 最小可用窗口 | 1024×720 | 小于此尺寸自动折叠次级面板 |

主导航从当前 `224px` 缩到 `184px`，品牌区只保留：

- `32×32px` 稿流标记；
- “稿流”产品名；
- 可选的一行简短状态，不重复“本地内容工作台”。

运行时就绪状态缩成底部一行状态按钮，点击后打开诊断，不永久占两行。

### 响应式策略

桌面端以生产力窗口为主，不照搬移动端：

| 窗口宽度 | 行为 |
| --- | --- |
| `≥ 1440px` | 主导航、文章列表、编辑器/预览、AI 侧栏全部可见 |
| `1180–1439px` | 文章列表默认 224px，AI 侧栏 320px |
| `1024–1179px` | 主导航进入 64px 紧凑态，文章列表可折叠，编辑器优先 |
| `< 1024px` | 主导航和文章列表改为抽屉；AI 侧栏覆盖式打开 |

面板尺寸和折叠状态按窗口保存。恢复时必须限制到当前窗口可用范围，不能让主编辑器被挤到不可用。

## ✍️ 文章工作区

### 页面结构

```text
┌──────┬────────────┬───────────────────────────────────┬─────────────┐
│ 主导航│ 文章列表   │ 标题 / 配图 / 发布 / 保存         │ AI 助手     │
│      │ 可折叠     ├───────────────────────────────────┤             │
│      │ 可拖宽度   │ 工具栏                            │ 当前任务卡  │
│      │            ├─────────────────┬─────────────────┤ 选中文本    │
│      │            │ Markdown 编辑器 │ 文章预览        │ 对话记录    │
│      │            │                 │                 │             │
│      │            ├─────────────────┴─────────────────┤ 输入框      │
│      │            │ 已保存 / 字数 / 模式              │             │
└──────┴────────────┴───────────────────────────────────┴─────────────┘
```

### 顶部动作

删除步骤条后，文章标题栏成为唯一页面级动作区：

- 左侧：折叠文章列表、文章状态、标题、修订号；
- 右侧：生成配图、发布、AI 完善全文、停止/保存；
- 只保留一个主操作：
  - 正在生成时为“停止生成”；
  - 正常编辑且有修改时为“保存”；
  - 已保存时主按钮退化为普通已保存状态，不用大块紫色。

动作超过宽度时进入“更多”，不挤压文章标题。

### 文章列表

- 默认宽度 `248px`；
- 支持拖动分隔条调整到 `208–320px`；
- 支持完全折叠；
- 折叠按钮位于文章页标题栏左侧；
- 折叠后从窗口左侧或按钮浮出，不改变主导航；
- 搜索框高度 `40px`；
- 列表项不画完整卡片边框，只用背景和左侧 `2px` 强调线表示当前文章；
- 标题最多两行，时间、状态和字数一行展示；
- 50 条以上虚拟化；
- 返回页面时恢复滚动位置和搜索词。

### 编辑器与预览

- 编辑区始终是页面的视觉中心；
- 编辑/预览比例默认 `1:1`，可拖动到 `35:65–65:35`；
- 单栏模式保留，切换控件使用分段按钮；
- Markdown 工具栏高 `44px`，图标点击区至少 `40×40px`；
- 编辑器行号区域变窄，正文左右内边距 `24px`；
- 预览正文最大阅读宽度 `720px`，在面板内水平居中；
- 文章替换使用轻微交叉淡入，不能先清空再闪现；
- 流式写入在编辑器内平滑显示，状态写入右侧任务卡；
- 粘贴/拖入图片时，只显示编辑器局部 Drop Overlay。

### AI 侧栏

AI 侧栏合并现有 `ArticleAssistant` 与 `WorkflowWorkspace`。

结构：

1. 标题栏：AI 助手、会话状态、折叠；
2. 当前任务卡：只在运行、失败、停止或刚完成时出现；
3. 已选文本 Chips；
4. 同一文章的对话消息；
5. Patch 预览、接受/拒绝/撤销；
6. 底部固定输入框。

当前任务卡显示：

- 当前 Agent 和动作；
- 简短阶段文字；
- 真实进度条或不确定进度状态；
- 已耗时；
- 停止；
- 折叠的详细步骤与日志；
- 失败时的原因、重试和复制诊断。

它取代：

- 底部 `WorkflowWorkspace`；
- `.article-progress` 悬浮卡；
- `.article-workflow-failure` 悬浮卡。

运行结束后任务卡折叠成一条会话事件，例如：

```text
✓ 写作完成 · 2 分 18 秒 · 使用 Tavily 2 次
```

点击才展开完整时间线。用户不需要同时看一个永久的“创作进度 3”面板。

### AI 消息样式

- 用户消息使用浅灰表面；
- AI 正文说明无气泡或使用白底；
- Patch 使用明确的增删差异，而不是一大段重复全文；
- 运行事件是紧凑系统行，不伪装成 AI 对话；
- 不展示隐藏思维链，只展示用户能理解的动作；
- 错误文案说明原因和下一步，不只显示英文 Provider 错误。

### 页面目标

素材库的第一任务是“快速看图、找到合适素材、选择并使用”，不是让用户在网格里编辑数据库。

```text
│ 24 张素材 · 已选 0 张                             排序 ▾  视图  │
├──────────────────────────────────────────────────────────────────┤

│ └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘ │
│ 标题          │ 标题          │ 标题          │ 标题          │

```

### 素材卡片

默认结构：

1. `4:3` 图片框，`14px` 圆角，`object-fit: cover`；
2. 左上：来源徽标，上传或 AI 生成；
3. 右上：预览和更多；
4. 左下或左上：独立选择按钮；
5. 图片下方：标题；
6. 最多两行客观描述；
7. 最多三个标签与尺寸/时间。

卡片默认没有外围边框和永久阴影。悬停只让图片轻微变暗并显示操作按钮，不放大卡片造成网格抖动。

选中状态：

- 图片外侧 `2px` 珊瑚色选择环；
- 选择按钮变为珊瑚色勾选；
- 卡片背景不整块变红；
- `aria-selected="true"`；
- 键盘空格可以选中。

### 详情抽屉

点击图片或“预览”打开右侧详情抽屉，宽度 `400–460px`：

- 完整图片，使用 `object-fit: contain`；
- 文件名、尺寸、格式、大小、创建时间；
- 客观图片描述；
- 使用场景；
- 标签；
- Alt 文本；
- 来源和生成模型；
- 生图 Prompt 折叠区；
- 正在使用这张图的文章；
- 插入当前文章、带入创作、重新生成、删除。

描述、使用场景和标签只在详情抽屉编辑，不在每张网格卡永久展开。

### 筛选和批量操作

筛选：

- 全部；
- 本地上传；
- AI 生成；
- 已使用；
- 未使用；
- 缺少描述。

排序：

- 最近添加；
- 最近使用；
- 名称；
- 文件大小。

选择图片后出现粘性批量操作条：

- 已选数量；
- 插入当前文章；
- 带入创作；
- 补充描述；
- 删除；
- 取消选择。

批量操作条不永久占据页面高度。

### 上传与拖拽

- 顶部“上传图片”为主要入口；
- 用户把文件拖到素材页时出现整页 Drop Zone；
- 上传中使用固定比例 Skeleton，避免网格跳动；
- 同哈希文件提示已存在并定位原素材；
- 非图片、超限和损坏文件在卡片位置显示错误与重试；
- 图片使用缩略图，详情才加载原图；
- 视口外图片懒加载并声明宽高；
- 50 张以上使用虚拟网格或分段加载。

### 空状态

空状态只包含：

- 一张轻量插图或图标；
- “还没有图片素材”；
- “上传图片”主按钮；
- “生成第一张图片”次按钮。

不展示无意义的长期运行状态或装饰机器人。

## 🧩 其他页面

### 创作页

- 保留一个大输入框作为页面中心；
- 模板、篇幅、联网和配图等选择使用输入框上方的紧凑 Chips；
- 高级参数收进 Popover/Sheet；
- 开始创作是唯一主操作；
- 最近文章和模板只作为下方辅助内容；
- 创建后立即跳文章页，运行状态由右侧 AI 侧栏接管；
- 不在创作页继续显示四步进度条。

### 模板页

- 左侧模板列表可按分类筛选；
- 右侧显示模板结构、文风、排版、固定块和参考原文；
- 模板卡只显示名称、用途、版本和更新时间；
- 参考原文与 Profile 在详情页/抽屉编辑；
- 固定开头/结尾用独立区块，不和 Markdown 骨架混成一个大文本框；
- 创建/抽取模板的进度使用页面内任务卡。

### 设置页

- 使用单列设置分类与右侧内容，不把所有配置做成同层级卡片；
- 文本模型、图像模型、联网工具、平台连接、本地数据和外观六组；
- 连接状态使用图标 + 文字，不能只靠颜色；
- Key 只提供重新输入和删除，不在 WebView 完整回显；
- 高级参数默认折叠；
- 保存按钮只在当前组有变更时出现；
- 错误就近显示并提供连接测试。

### 发布弹窗

- 保持白底；
- 平台卡使用真实图标、账号脱敏名和能力；
- 已登录、需登录、不支持当前操作三种状态同时有文字；
- 选择区可滚动，底部确认操作固定；
- 默认动作明确写“保存到草稿”或“填充编辑器”，不笼统写“发布”；
- 修订变化后弹窗立即提示确认失效。

## 🧱 组件和代码结构

### 公共组件

重构时先建立小型内部组件层，不引入大型 UI 组件库：

```text
components/ui/
  Button.tsx
  IconButton.tsx
  Badge.tsx
  Chip.tsx
  SegmentedControl.tsx
  SearchField.tsx
  Popover.tsx
  Dialog.tsx
  Drawer.tsx
  ResizablePanel.tsx
  ProgressBar.tsx
  EmptyState.tsx
  Skeleton.tsx
  Tooltip.tsx
```

继续使用 Lucide 图标，统一 `18px / strokeWidth 1.8`。只有重要动作可以配文字，不能堆图标。

不立即引入 Ant Design、Material UI 或完整 shadcn。浮层、焦点管理等复杂基础能力可以在实现阶段评估轻量无样式 Primitive，但必须先比较包体和现有 Tauri 兼容性。

### 业务组件拆分

```text
features/articles/
  ArticleWorkspace.tsx
  ArticleListPanel.tsx
  ArticleHeader.tsx
  ArticleAssistantPanel.tsx
  ArticleRunCard.tsx

features/media/
  MediaGallery.tsx
  MediaCard.tsx
  MediaToolbar.tsx
  MediaDetailDrawer.tsx
  MediaSelectionBar.tsx

features/templates/
  TemplateListPanel.tsx
  TemplateDetail.tsx
```

视觉重构不能顺便重写业务状态。先从现有组件提取 UI，再把 `App.tsx` 中对应状态逐步迁到 feature hook。

### CSS 拆分

将单一 `styles.css` 迁移为：

```text
styles/
  tokens.css
  reset.css
  typography.css
  layout.css
  motion.css
  utilities.css
  components/
  features/
```

采用 CSS Layers：

```css
@layer reset, tokens, base, components, features, utilities, overrides;
```

规则：

- 组件只使用语义 Token，不直接散落十六进制颜色；
- 页面选择器不超过三层；
- 禁止在文件尾继续追加一行式覆盖；
- 不使用 `!important` 修复层级；
- 暗色主题单独映射 Token，不复制全部组件规则；
- 每迁移一组组件就删除旧样式，不能永久双轨。

### 状态整合

UI 只消费统一运行视图模型：

```ts
interface ArticleRunView {
  runId: string;
  status: "queued" | "running" | "completed" | "failed" | "cancelled";
  agentLabel: string;
  phase: string;
  detail: string;
  progress: number | null;
  elapsedMs: number;
  canCancel: boolean;
  canRetry: boolean;
  events: RunEvent[];
  error?: {
    code: string;
    message: string;
    recovery: string;
  };
}
```

`ArticleAssistantPanel` 使用它渲染任务卡；其他组件不得再各自推断“是否正在运行”。

## ♿ 交互与可访问性

### 键盘

- `Ctrl/Cmd + N`：新文章；
- `Ctrl/Cmd + S`：保存；
- `Ctrl/Cmd + Shift + P`：打开发布弹窗；
- `Ctrl/Cmd + /`：聚焦 AI 输入；
- `Esc`：关闭当前 Popover/Drawer/Dialog；
- 素材网格方向键移动，空格选择，Enter 预览；
- 面板分隔条支持方向键调整宽度；
- 所有图标按钮具有中文 `aria-label`。

### 焦点

- 焦点环使用 `2px --color-accent`，与控件间隔 `2px`；
- 模态框和抽屉打开后聚焦标题或第一个字段；
- 关闭后焦点回到触发按钮；
- 页面切换后焦点进入页面标题；
- Toast 使用 `aria-live="polite"`，错误使用 `role="alert"`；
- 运行状态更新不抢走编辑器焦点。

### 操作尺寸

- 主要按钮高 `40–44px`；
- 图标按钮视觉尺寸 `32–36px`，命中区域至少 `40×40px`；
- 高风险删除与普通操作分开；
- 拖拽必须有按钮替代方案；
- 不能只依赖 hover 展示关键操作。

### 对比度

- 普通文字与背景至少 `4.5:1`；
- 大图标与边界至少 `3:1`；
- 选中、错误和成功都同时显示图标或文字；
- 浅灰辅助文字不承载关键说明。
